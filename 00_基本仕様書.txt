# 法令チェック ＆ AI添削システム 開発ナレッジ・アーキテクチャ仕様書

## 1. プロジェクト概要
ユーザーが入力した法令に関する文章（略称・通称含む）から該当する法令・条文を特定し、国が提供する「e-Gov 法令API Version 2」から公式条文XMLをピンポイントで取得・照合。Gemini API を用いて法令適合性、本則・経過措置の適用関係、実務解釈を監査し、具体的な改善文案と法的根拠を即座に提示するリーガルチェックシステム。

## 2. システム構成と動作フロー (v16 現在)
1. **略称・通称の自動正規化 (Gemini)**:
   - 「労基法」「健保法」「パワハラ防止法」等の俗称・略称を e-Gov 登録の公式法令名に自動変換。
   - 文章中に条番号の直接記載がない場合、文脈から該当する条文（例: 賃金請求権時効 ➡️ 第115条、第143条）を逆引き特定。
2. **公式条文のピンポイント取得 (e-Gov 法令API Version 2)**:
   - `GET /laws?law_title=...` で法令IDを取得。
   - `GET /law_revisions/{law_id}` で現行・廃止の有効ステータスを確認。
   - `GET /law_data/{law_id}` で最新XMLを取得し、漢数字・算用数字を正規化して該当条文ブロック（見出し・項番号・本文）をパース。
3. **政省令（委任規定）の連鎖把握**:
   - 条文内に「政令・省令で定める」等の委任がある場合、連鎖して参照すべき施行令・施行規則（例: 労働基準法施行規則）を特定・追加取得。
4. **法的根拠の厳密な峻別と監査レポート生成 (Gemini 3.8 Flash)**:
   - 「(A) 国の公式条文に基づく確定事実（第○条第○項第○号までピンポイント特定）」と「(B) 実務・判例・省庁指針等に基づく補足（AI判断根拠）」を明確に枠を分けて出力。
   - ハルシネーションを抑止しつつ、実務上不可欠な指針（経産省「営業秘密管理指針」や労基法附則第143条第2項の経過措置など）を正確に適用。
5. **UI & トークン管理**:
   - Colab / ipywidgets による対話型フォーム画面（入力エリア＋ボタン）。
   - レスポンスごとに消費トークン数（入力・出力・合計）を自動集計・表示。

## 3. 解決した主要エラー・技術的知見
- **e-Gov API の法令特定**:
  - 法令名が略称やキーワードの場合、`/laws` だけでなく `/keyword` API へのフォールバックを実装して完全ヒットを実現。
- **Gemini API 呼び出しの安定化**:
  - 外部ライブラリ依存（pip）を排除し、Python標準 `urllib` による REST API 直接通信を採用。
  - 最新推奨モデル `gemini-3.8-flash` を指定。
  - HTTP 503（一時混雑）や HTTP 429 に対する指数バックオフ自動再試行（リトライ）を実装。
- **条文ブロックの渡し方**:
  - 項（Paragraph）単位の安易な切り出しは除外規定や適用条件の見落としを招くため、「条（Article）単位」で渡す設計が法的一貫性・正確性の観点から最善。
- **外部非API情報（ガイドライン・監督指針）の扱い**:
  - URL提示だけではAIは閲覧できないため、Markdown（.md）としてテキスト化してローカル配置・注入する方式が最も堅牢かつ高精度。

## 4. コスト・スケーラビリティ
- 1回のチェックあたりの消費量: 約 2,500〜5,000 トークン（API呼出 2〜3回）。
- Google AI Studio 無料枠（1日1,500リクエスト）の範囲内で、1日あたり約500〜750回、月間約2万回以上のチェックが完全費用0円で稼働可能。
