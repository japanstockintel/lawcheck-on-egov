# ③_開発実績および実装済み機能一覧

## 1. これまでに実現・完成しているコア機能一覧

本プロジェクトにおいて、設計・実装および検証が完了している主要機能は以下の通りである。

### 1.1 略称・俗称の自動正式名称変換
* **概要**: ユーザーが入力した文章中の「労基法」「健保法」「パワハラ防止法」「育休法」「不競法」「iDeCo（確定拠出年金）」などの略称・俗称を、Gemini NLP を用いて e-Gov 登録の正式法令名称（例: `労働基準法`, `労働施策の総合的な推進等に関する法律` 等）へ高精度に自動変換する。

### 1.2 ピンポイント条文・項・号の特定と抽出
* **概要**: 文章中に「第36条」などの具体的な条番号が書かれていない場合でも、文脈から該当する可能性の高い条文番号（本則・附則・経過措置を含む）を推測・特定し、e-Gov API の XML から当該条文のテキストのみをピンポイント抽出する。

### 1.3 政省令（委任規定）の自動連鎖特定
* **概要**: 法律本文中に「政令で定める」「省令で定める」といった委任規定が含まれている場合、Gemini が参照すべき具体的な政省令名（例: `労働基準法施行規則` 等）と条番号を特定し、API から連鎖的に追加取得してエビデンスとして提示する。

### 1.4 確定事実（e-Gov）と AI 解釈の厳密な峻別出力
* **概要**: 生成される添削レポートにおいて、根拠を以下の2つの枠に明確に分離して表示する。
  * **(A) 🏛️ 国の公式条文に基づく確定事実**: e-Gov API から取得した第○条第○項第○号までの確定根拠。
  * **(B) 💡 実務・判例・省庁指針等に基づく補足**: ガイドライン、省庁指針、判例実務等に基づく AI の補足解説。

### 1.5 厳格な AI プロンプトガードレール（決めつけ・断定の禁止）
* **概要**: e-Gov API の現行データに存在しない記述（未施行の改正予定や個別省庁通知など）が入力された場合、AI が勝手に「ユーザーの誤記・勘違いだ」と過剰に断定・攻撃的な判定を行うことを禁止するプロンプト指示を固定化。
* **効果**: 「現行データでは照合できないが、最新の行政通知等の可能性があるため公式発表をご確認ください」といった誠実かつ安全な回答を実現。

### 1.6 トークンカウンター ＆ コスト完全0円運用
* **概要**: Gemini API から返却される `usageMetadata` を自動集計し、入力トークン・出力トークン・API通信回数をリアルタイムトラッキング。1回のチェックで消費するトークン量を可視化し、完全無料枠内で安全に運用可能。

## 2. 実装済みコードコンポーネント構造

`app.py` において確立された関数群の役割は以下の通り。

```python
# 1. call_gemini_api()
#    Gemini REST API (v1beta/models/gemini-3.8-flash:generateContent) を直接呼び出し。
#    タイムアウト45秒、指数バックオフ再試行、HTTP 429/503 エラーの日本語適切な処理。

# 2. EGovLawAPIClient
#    e-Gov API v2 クライアント。get_laws(), search_keyword(), find_law(), 
#    get_law_revisions(), get_law_data(), parse_amendment_status() を実装。

# 3. normalize_article_num() / extract_article_from_xml()
#    漢数字・全角数字の半角正規化、および ElementTree による条文パース。

# 4. parse_law_references_with_gemini()
#    Gemini NLP による法令名変換 ＆ 文脈条文特定。JSON出力フォールバックパース対応。

# 5. detect_delegated_regulations()
#    政省令委任規定の自動検出。

# 6. audit_with_gemini()
#    決めつけ禁止ガードレールを搭載した最終法的監査レポート生成エンジン。

# 7. main()
#    Streamlit UI レイアウト、B2B SaaS 風 CSS、サイドバー AdSense 4大要素、
#    入力窓直下のエクスキューズボックス、実行ステータス表示。
```
