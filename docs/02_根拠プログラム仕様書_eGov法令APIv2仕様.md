# ②_根拠プログラム仕様書_eGov法令APIv2仕様

## 1. e-Gov 法令API Version 2 の概要と特徴
本システムは、デジタル庁が運用する「e-Gov 法令API Version 2 (`https://laws.e-gov.go.jp/api/2`)」を直接呼び出し、日本国の公式現行法令データをリアルタイムで参照する。

### API v2 の主な特徴
1. **JSON プレビュー対応**: 一部エンドポイントで `response_format=json` によるメタデータ取得が可能。
2. **生の XML 条文配信**: `/law_data` エンドポイントより、完全な法制執務構造を持つ公式条文 XML を直接ダウンロード可能。
3. **改正履歴（Revision）管理**: 法令の新規制定、一部改正、廃止、失効などの状態変更を `law_revisions` で一覧トラッキング可能。

---

## 2. システムで使用する主要エンドポイント一覧

| エンドポイント | リクエストパラメータ | 取得データ・用途 |
| :--- | :--- | :--- |
| **`GET /laws`** | `law_title` (正式法令名) | 正式法令名に合致する法令基本情報（`law_id`, `law_num`等）の検索 |
| **`GET /keyword`** | `keyword` (キーワード) | 法令名または本文キーワードによる全件検索（`/laws` でヒットしない場合のフォールバック） |
| **`GET /law_revisions/{law_id}`** | `response_format=json` | 該当法令の改正履歴一覧、最新リビジョン情報、改正区分、施行日メタデータの取得 |
| **`GET /law_data/{law_id}`** | `response_format=xml` | 本日時点で施行されている公式現行条文の全本文 XML データの取得 |

## 3. 改正区分の定義およびAPIの技術的限界（重要仕様）

### 3.1 APIにおける改正区分（`amendment_type` / `mission`）
e-Gov API の `revision_info` では、法令の状態変更が以下の通り区分されている。

* **新規制定**: `amendment_type = "1"` かつ `mission = "New"`
* **一部改正**: `mission = "Partial"`（既存法令の数値・条文の一部変更）
* **被改正法**: `amendment_type = "3"` かつ `mission = "New"`
* **廃止・失効**: `amendment_type = "8"` または `repeal_status` が `"Repeal"`, `"Expire"`

### 3.2 未施行・将来の改正予定に関する技術的限界
本システムの開発および検証過程で判明した、e-Gov API のデータ構造上の最も重要な限界は以下の通りである。

1. **現行条文 XML（`/law_data`）は「施行日」まで更新されない**
   - 国会で公布済みの改正法であっても、**実際の施行予定日（例: 2026年12月1日）を迎えるまでは、現行法本文 XML の内容は旧法のまま書き換わらない**。
2. **改正履歴（`/law_revisions`）にはメタデータのみ格納されている**
   - 改正履歴からは「施行予定日」「改正法名」などのメタ情報は取得できるが、「具体的にどの条文がどう変わるか」という未来の本文 XML テキストはAPIから配信されない。
3. **一部改正法（束ね法）の構造**
   - 制度改正の多くは単一の基本法名ではなく、「社会経済の変化を踏まえた...一部を改正する等の法律」といった長大な束ね法として公布されるため、単一法名からの検索に限界がある。

### 3.3 本限界に対するシステムの対応方針
API から未施行の本文 XML が配信されないため、**「本日時点で施行されている国の公式現行条文を基準にリアルタイム照合する」** ことを本システムの絶対的な照合基準（エクスキューズ）として UI に明記し、未照合データについては Gemini の補足知見を組み合わせる設計とする。

## 4. 条文抽出ロジック ＆ XML パース処理

### 4.1 条文番号の正規化 (`normalize_article_num`)
ユーザーや Gemini から渡される条文番号表記（例: 「第36条」「第３６条」「三十六条」）を、XML の属性値 `Num` に合致するアラビア数字形式（例: `36`）へ自動変換する。

### 4.2 XML パース（`extract_article_from_xml`）
Python の `xml.etree.ElementTree` を使用し、以下のタグ構造から本文をピンポイント抽出する。
* **`<Article Num="36">`**: 該当条文ノードの探索
* **`<ArticleCaption>`**: 条文見出し（例: `（時間外及び休日の労働）`）
* **`<ArticleTitle>`**: 条文タイトル（例: `第三十六条`）
* **`<Paragraph>` / `<ParagraphNum>` / `<Sentence>`**: 項番号および本文テキストの連結抽出
